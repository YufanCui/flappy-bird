# 按键延迟下的理论上限（2026-11-19）

## 1. 问题
Round 4 中，开口随机 + 5% 按键延迟下所有 model 都只有约 20 根柱子。瓶颈在 agent（学得不够好），还是在环境（这个难度本身就飞不远）？

## 2. 方法（`../../theoretical_bound_sticky_v1.py`，精确计算，不涉及学习）
- 柱子的出现与小鸟的动作无关，所以对每个 episode seed 可以先记录整局的柱子位置（与评估用的 20 个 seeds 230000–230019 完全相同）。
- 小鸟状态 = (高度, 速度, 上一步实际执行的动作)；物理和碰撞完全照搬原版代码。
- 用动态规划（backward induction）求“最优策略”能连续通过 k 根柱子的最大概率 S_k。
  这个最优策略**提前知道所有柱子的位置**，但不知道未来哪一步会被延迟。它比小鸟实际能获得的信息更多，
  所以 S_k 是**上限**：任何 policy 通过 k 根的概率都 ≤ S_k；平均柱子数 ≤ Σ S_k。
- **验证：** 1,480 步随机动作下，模拟的高度、速度、存活与真实环境逐步一致（0 处不符）；碰撞判断与 `env._check_crash` 一致（0 处不符）；
  没有延迟时最优策略的存活概率是 1，与之前的可行性搜索一致。见 `validation.json`。

## 3. 结果（20 个 seeds 平均）

| 环境 | 延迟 p | 通过 20 根 | 通过 100 根 | 通过 500 根 | 前 500 根内平均柱子数上限 |
|---|---:|---:|---:|---:|---:|
| 开口随机 80–120 | 0 | 100% | 100% | 100% | 500 |
| | 1% | 99.9% | 99.7% | 98.2% | 497 |
| | 2% | 99.8% | 98.6% | 92.7% | 489 |
| | **5%** | **98.1%** | **89.6%** | **56.9%** | **425** |
| | 10% | 90.7% | 56.9% | 5.6% | 236 |
| | 25% | 35.4% | 0.3% | 0% | 29 |
| 原游戏（开口 100） | 5% | 99.5% | 97.5% | 88.0% | 482 |
| | 10% | 95.8% | 80.3% | 32.7% | 366 |
| | 25% | 47.6% | 2.2% | 0% | 40 |

## 4. 结论
1. **之前的推测（“5% 延迟本身就让平均只能飞约 20 根”）是错的。** 在开口随机 + 5% 延迟下，上限是前 500 根内平均最多约 425 根；
   有 57% 的概率能连续通过 500 根。我们的 agents 只有约 20 根。
2. 上限假设“知道所有柱子位置”，真实可达到的成绩会低一些，但很难解释 20 倍的差距。**瓶颈很可能主要在 agent。**
3. 延迟概率越大，上限下降越快：25% 时（Atari 研究常用的值）上限只有约 29 根，说明在 Flappy Bird 里 25% 太高；5% 是“有挑战但可以飞很远”的设定。

## 5. 下一步（agent 方面）
- agent 为什么学不好？候选（都是假设）：训练量不够（延迟让学习信号更嘈杂）；observation 不直接包含“上一步实际执行的动作”；
  PPO 的 deterministic 评估没有为“可能被延迟”留余量。可以逐一做对照实验。
