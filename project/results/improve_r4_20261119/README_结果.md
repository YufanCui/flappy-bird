# Round 4 结果记录（2026-11-19 15:10 评估完成）

## 1. 做了什么改动
- **环境：** 两种 randomness：上下开口大小随机 80–120（老师要求的），加上 **sticky actions 5%**（每一步有 5% 的概率，机器重复上一步动作，不执行这一步的选择；模拟按键延迟）。水平距离恢复原游戏。
- **训练：** stack4 + learning rate 线性衰减 + 3M steps，seeds 0–2。两组 reward：原版 vs 6 月 Exp B（top penalty −2）。
- **评估：** deterministic，同一组 20 个 episode seeds，**每局上限 40,000 步（约 1,000 根柱子）**。
- **参照：** round 3 的 `lr3M` models（训练时没有 sticky），在同样条件、同样上限下评估（`../sticky_probe_20261119/eval/*_cap40k.csv`）。

## 2. 增加了什么 randomness
sticky actions（按键延迟），p = 0.05。选择依据见 `../sticky_probe_20261119/README.md`。

## 3. 结果（平均完整穿过的柱子数；括号 = 飞满 40,000 步的比例）

| 训练方式 | **开口随机 + 延迟（主要）** | 开口随机 | 原游戏 | 原游戏 + 延迟 |
|---|---:|---:|---:|---:|
| 参照：训练时无延迟，原版 reward | 18.6（seeds 16.8 / 21.2 / 17.8） | 101.0 | 700.7（48%） | 32.7 |
| 训练时有延迟，原版 reward | 20.1（21.8 / 18.6 / 19.8） | 100.4 | **771.2（48%）** | 47.0 |
| 训练时有延迟，Exp B reward | 20.0（21.8 / 20.1 / 18.1） | 120.2 | 524.1（30%） | 48.1 |

主要条件下每个 model 的中位数都在 13–25 根之间，最好一局 104 根。原游戏中，原版 reward seed 0 平均 1,055.7 根（几乎每局都飞满约 1,061 根）。

## 4. randomness / 改动有没有帮助？
1. **用延迟环境训练，只带来很小的提升**：主要条件下 20.1 vs 18.6（+8%），seeds 有重叠，**不能算可靠的改善**。
   在“原游戏 + 延迟”上提升更明显（47 vs 33）。
2. **Exp B reward 在新环境中没有带来改善**：主要条件 20.0 vs 20.1，几乎相同；原游戏上平均更低（524 vs 771），但 seed 间差异很大（202–920），也不能下“更差”的结论。
3. **5% 的按键延迟是目前最大的瓶颈**：没有延迟时能飞约 100（随机开口）到 700+（原游戏）根；有延迟时只剩 20–50 根，而且训练时加入延迟也几乎补不回来。

## 5. 解读与推测（未验证）
- 如果每通过一根柱子都有约 5% 的概率因为延迟而失败，平均就只能飞约 20 根，这与观察到的结果一致。
  **推测**：在开口很小（80 附近）时，一次“多出来的跳跃”或“晚一帧的跳跃”可能在物理上就无法挽回；那么问题可能不在 agent，而在这个难度本身的上限。
- 这可以用精确搜索（考虑 sticky 概率的最优策略）来检验，目前还没有做。
- 局限：3 seeds；development 评估；Exp B 为按记录重新实现。

## 6. 下一步候选（给老师讨论）
- 先检验 5% 延迟下的“理论最好成绩”，判断瓶颈是 agent 还是环境本身。
- 若 agent 仍有空间：训练更久、recurrent policy（让 agent 记住上一步实际执行了什么）、或在 observation 中加入“上一步实际执行的动作”。
- 若接近理论上限：降低延迟概率（如 1–2%），或只在较宽的开口中加入延迟。
