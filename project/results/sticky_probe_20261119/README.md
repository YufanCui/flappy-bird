# Sticky-action probe（2026-11-19，选 sticky 概率之前的诊断）
目的：在正式训练之前，看 sticky actions 的概率 p 会让任务难多少，以便选一个“有挑战、但不是不可能”的 p。
做法：直接用 round 3 最好的 models（`gap80_120+stack4_lr3M` seeds 0–2，复制自 `../improve_r3_20261118/`，**训练时没有 sticky**），
在随机开口 80–120 + sticky p ∈ {0, 0.05, 0.10, 0.25} 上 deterministic 评估 20 局，每局上限 10,000 步。不训练。
注意：这只是诊断；用这些评估结果来选 p 属于 development 决策。

## 结果（平均完整穿过的柱子数，seeds 0/1/2）
| sticky p | 平均 | seeds |
|---|---:|---|
| 0（无） | 92.1 | 96.2 / 110.9 / 69.2 |
| 0.05 | 18.6 | 16.8 / 21.2 / 17.8 |
| 0.10 | 10.7 | 11.5 / 11.4 / 9.2 |
| 0.25 | 4.6 | 5.7 / 3.6 / 4.5 |

**发现：** 没见过按键延迟的 policy 非常脆弱：只要 5% 的步骤重复上一步动作，成绩就从 92 跌到 19。
**选择：** 正式实验用 p = 0.05。理由：环境每步是一帧（约 30 FPS），5% 约等于每 0.7 秒有一次一帧的输入偏差，
接近真人操作的不精确；已经足以显著提高难度。Atari 研究常用 0.25，但那里每个动作会持续多帧，与这里不可直接比较。
